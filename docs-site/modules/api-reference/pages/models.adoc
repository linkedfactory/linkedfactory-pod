= RDF model import and export
:description: Import, export, replace, and delete Pod asset-description models through eniLINK.

Use eniLINK's model API to load asset descriptions, exchange ontologies, or export RDF.
These operations act on semantic models, not on Pod measurement values.

include::platform-basics:partial$upstream-scope.adoc[]

== Routes and operations

`/models` and `/vocab` use the same RDF model handler.
Supply an absolute model IRI with the `model` parameter.

[cols="1,2",options="header"]
|===
|Request |Behavior

|GET `/models?model=...`
|Export the selected model using a registered RDF writer.

|POST `/models?model=...` with an RDF body
|Load RDF into the model, creating it if needed and permitted. Existing statements are retained.

|PUT `/models?model=...` with an RDF body
|Clear the existing model, then load the supplied RDF. Create the model if absent and permitted.

|DELETE `/models?model=...`
|Clear and remove the model and its model metadata.

|OPTIONS `/models`
|Return an empty successful response; this is not a model-listing operation.
|===

The handler also accepts `query` on model GET and POST requests when wired with its SPARQL handler.
Prefer the explicit xref:platform-basics:sparql.adoc[SPARQL interface] for query clients.
GET `/models` without a model selection is the browser model-list page, not a JSON collection endpoint.

== Import an asset description

Save the Turtle example from xref:user-guide:modeling-assets.adoc[] as `assets.ttl`.
For the isolated development configuration:

[source,bash]
----
export POD_URL='http://localhost:8080'
export POD_MODEL='http://linkedfactory.github.io/data/'

curl --fail-with-body \
  "$POD_URL/models?model=$POD_MODEL" \
  --header 'Content-Type: text/turtle' \
  --data-binary @assets.ttl
----

The example model IRI can be used literally in this query string.
Percent-encode model parameter values containing reserved characters such as `&` or `#`.
For production, add the deployment's verified authentication options.

A successful import returns HTTP `200`.
Verify the statements with SPARQL rather than expecting an RDF response body.
POST adds RDF; it is not a resource-level replacement operation.
Repeated documents containing anonymous blank nodes can create additional structures.

For JSON-LD, use `Content-Type: application/ld+json` and the payload from xref:api-reference:json-ld.adoc[].
The upstream tests cover JSON-LD import and export.
The corresponding codec must still be installed.

== Export a model

[source,bash]
----
curl --fail-with-body --get \
  "$POD_URL/models" \
  --header 'Accept: text/turtle' \
  --data-urlencode "model=$POD_MODEL" \
  --output assets-export.ttl
----

Use `Accept: application/ld+json` to request JSON-LD when a writer is registered.
An export is an RDF graph representation, not an archive of the KVIN store, binary attachments, or all administrative metadata.

== Select the model and format explicitly

Without `model`, a path such as `/models/example` identifies a model using the request URL.
This can make graph identity depend on the public host or proxy URL.
The implementation also uses filename extensions during model lookup and creation.
Prefer explicit model IRIs without serialization suffixes, and select formats with headers.

The `type` parameter can override content-type selection.
Otherwise the handler uses request headers, registered RDF content types, and supported filename extensions.
For automated clients, send `Content-Type` on imports and `Accept` on exports.
Browser requests accepting HTML can be rewritten to an ontology presentation.

== Replacement and deletion precautions

[IMPORTANT]
====
PUT clears the model before validating and loading the new representation.
An unsupported media type or invalid document can therefore leave existing data cleared.
Do not assume transactional replacement or rollback.

Validate input and export a backup before replacement.
Use a staging model when preparing a production change.
====

DELETE removes the RDF model and its metadata; it is not a request to delete matching KVIN measurements or attachment files.
Coordinate lifecycle changes across the interfaces.

== Response handling

[cols="1,2",options="header"]
|===
|Status |Meaning

|200
|The requested import, replacement, or deletion completed.

|400
|Invalid model selection or RDF input, depending on the request path.

|403
|The resolved model is not accessible to the caller.

|404
|The requested model was not found for export or deletion.

|415
|No suitable RDF reader or writer was selected.
|===

These are not the time-series API's JSON error objects.
Also handle infrastructure errors and incomplete streamed exports.
See xref:platform-basics:managing-models.adoc[] for imports and model organization.
