= eniLINK source baseline
:description: The eniLINK revision the documentation is based on, and where each eniLINK feature used by Pod is implemented.

The pages about eniLINK functionality are based on https://github.com/enilink/enilink/tree/{enilink-source-revision}[eniLINK revision {enilink-source-revision}].
Pod's build depends on an eniLINK snapshot version, which can point to a newer revision; when updating the documentation, check the behaviour against the revision actually used and update the attribute `enilink-source-revision` in `docs/antora.yml`.

A Pod distribution can contain a different eniLINK build or leave out optional bundles and RDF codecs.
Features described here are therefore only available if the distribution includes them.

== Choose an interface by responsibility

Use xref:reference:models-api.adoc[] for asset-description graphs, xref:reference:files-api.adoc[] for attachment bytes, and xref:reference:time-series-api.adoc[] for measurements.
Use xref:how-to:use-sparql.adoc[] to query descriptions or join them with KVIN data.
Keep configuration graphs and access-control metadata separate from ordinary asset imports.
